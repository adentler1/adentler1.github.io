# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

This repository is Alexander Dentler's personal academic website. It is published automatically by GitHub Pages at https://adentler1.github.io/ — any commit pushed to `main` goes live within about a minute, with no build step in between. The site is five plain HTML files plus one shared CSS file. There is no JavaScript framework, no package manager (no `package.json`), and no template engine: what you see in each `.html` file is exactly what gets served.

## Previewing your changes

There is nothing to install and nothing to build. To check a change:
1. Open the edited `.html` file directly in a browser, **or**
2. Run `python3 -m http.server` from the repo root and visit `http://localhost:8000/index.html` (this is more reliable than opening the file directly, because relative links to `assets/` and `css/` resolve the same way they will on the live site).

There are no automated tests, linters, or CI checks in this repo — visually reviewing the page in a browser is the only verification step.

## The five pages

| File | What it is |
|---|---|
| `index.html` | Homepage: intro/hero, a featured item, recent lectures, a short list of selected research, a short list of projects, and contact info |
| `research.html` | Full list of publications and working papers. Unlike the other pages, this one is generated by JavaScript from a data list — see "Editing the research list" below |
| `projects.html` | Applied/non-academic projects: Monitoring Mexico (and its two sub-projects, @LiquidMexico and Monitoring Minutes) and Soccer Contributions |
| `teaching.html` | Teaching philosophy, courses taught, pedagogy |
| `cv.html` | CV content plus links to download the CV as a PDF |

`css/style.css` is the one stylesheet, shared by all five pages. `assets/` holds every PDF and image, grouped into subfolders by project or talk series (e.g. `assets/DVP/`, `assets/LiquidMexico/`, `assets/Talks/`).

## Important: there is no shared header/footer file

Each `.html` file is fully self-contained — it repeats its own copy of the `<head>` (title, description, social-preview tags, favicon, stylesheet link, analytics script) and its own copy of the site header (logo + nav links) and footer. **This means the same block of markup is duplicated five times across the repo.** If you change the navigation, the footer, or anything else that should look the same on every page, you must make that same edit in all five `.html` files by hand — there is no include mechanism that will propagate it for you.

Two details that differ page-to-page and are easy to miss when copying this markup:
- The nav link for the current page has `aria-current="page"` added to it (e.g. on `research.html`, the "Research" link has this attribute; the other four links don't).
- The `<title>`, meta description, and Open Graph/Twitter tags in `<head>` are unique per page and should describe that page's actual content, not be copy-pasted verbatim.

## Editing the research list (`research.html`)

This is the only page with real logic behind it, so it deserves a closer look.

Near the bottom of `research.html` is an inline `<script>` block. Inside it is a JavaScript array called `papers` — this array **is** the content of the page; there is no separate data file. Each entry in the array is one publication, for example:

```js
{
  id: "crime-paper",                    // becomes the URL anchor: research.html#crime-paper
  title: "Measuring Residents' Willingness to Pay to Avoid Crime",
  authors: "Alexander Dentler and Enzo Rossi",
  venue: "Journal of Housing Economics 66: 102024",
  year: 2024,
  status: "published",                  // one of: accepted, published, policy, submitted, wip
  topics: ["living-standards"],         // must match a key in the topicMeta object above the papers array
  abstract: "...",                      // full abstract text, shown in "Abstract" display mode
  bullets: ["...", "..."],              // short summary points, shown in "Key points" display mode
  links: [{ label: "Journal article", url: "https://..." }],
  wp: null                              // or an object describing an earlier working-paper version (see below)
}
```

**To add a new publication:** add a new object to the `papers` array following this shape. Nothing else needs to change — the page reads the array on load and builds the HTML itself.

**To link to a specific publication from another page** (e.g. from the "Selected Research" list on `index.html`), point to `research.html#<id>`, using that entry's `id` field. Because other pages link to these ids directly, don't rename an `id` that's already referenced elsewhere without also updating those links.

**If a paper has an earlier working-paper version**, fill in the optional `wp` object instead of leaving it `null`:
```js
wp: {
  title: "Earlier title of the working paper",
  ref: "SNB Working Paper 2021-20",
  delta: "A sentence or two on what changed between the working paper and the published version.",
  bullets: ["optional short summary points for the working paper version"]
}
```

**What controls the page's two toggle rows** (visible at the top of `research.html` as "Sort" and "Show" buttons):
- The "Sort" toggle switches between chronological order and grouping by topic. Within chronological order, papers are grouped by `status` first (in the order listed in `statusOrder`), then newest-year-first within each group. Within topic order, papers are grouped by `topics`, in the order set by the `order` field on each entry in `topicMeta`.
- The "Show" toggle switches between showing the full `abstract`, the short `bullets`, or just the title.

You do not need to edit any of the rendering code to add or update a paper — only the `papers` array (and, if you're introducing a new topic, the `topicMeta` object just above it).

## Styling (`css/style.css`)

**Colors and dark mode:** every color used on the site is defined once as a CSS variable at the top of the file (e.g. `--background`, `--text`, `--accent`, `--muted`, `--border`), then re-defined with different values inside an `@media (prefers-color-scheme: dark)` block further down. This means the site automatically switches to a dark palette when the visitor's OS/browser is set to dark mode — there is no manual light/dark switch on the page itself. When adding a new color, define it as a variable in both places rather than hardcoding a hex value in a rule, otherwise it won't adapt to dark mode.

**Reusable layout classes** — these appear throughout the HTML files and are defined once in `style.css`:
| Class | Used for |
|---|---|
| `.section`, `.section-header` | A titled block of content on a page (e.g. "Selected Research" on the homepage) |
| `.entry`, `.card` | One item in a list (a publication, a project, a lecture). Each gets a small decorative line above it, except the first item in a list |
| `.stack` | Vertical spacing between a group of `.entry`/`.card` items |
| `.link-row` | A horizontal row of outbound links below an item (e.g. "Journal article", "Working paper version") |
| `.tag`, `.tag--published`, `.tag--policy`, `.tag--submitted`, `.tag--wip` | The small colored status pill next to a publication title |
| `.project-entry`, `.subproject` | The two-level project structure on `projects.html` (a top-level project containing indented sub-projects) |
| `.carousel`, `.carousel-track` | The horizontally scrollable strip of images (used for @LiquidMexico visualizations) |
| `.wp-note` | The highlighted callout box describing an earlier working-paper version |

**Outbound links:** any link that leaves the site (a journal page, an external project, a social profile) should have `target="_blank" rel="noopener noreferrer"`, matching the existing links.

**Page width:** two CSS variables control how wide content is allowed to get — `--max-width` (720px) for body/prose content, `--nav-width` (1040px, wider) for the header bar — both are horizontally centered.

## Analytics
